\subsection{Flow Matching Policy vs. MSE Policy}
The flow policy agent takes actions to achieve the goal in a more orderly and consistent way.
In contrast the MSE policy agent either achieves the goal quickly and efficiently or it gets very off track and performs actions that appear not to be leading directly toward pushing the T to the target location. A few hypothesese as to what might be going wrong here: 
\begin{itemize}
\item the MSE policy isn't as equipped to handle multimodal distributions and when in a scenario where it should pick a mode it instead splits the difference leading to a suboptimal action.
\item the MSE policy may be less consistent because its predictions are worse than the flow policy and as a result it gets out of distribution more often.
\end{itemize}

\begin{itemize}
\item Which value estimator has better performance without advantage normalization: the trajectory-centric one, or the one using reward-to-go?
\begin{itemize}
\item Reward to go (RTG) has better performance without advantage normalization. You can see that RTG converges to 200 in both the large and small batch cases whereas the baseline does not in the small batch case.
\end{itemize}
\item Between the two value estimators, why do you think one is generally preferred over the other?
\begin{itemize}
\item The RTG esimator delivers higher avg return and lower stdev return when advantage normalization is not used.
\end{itemize}
\item Did advantage normalization help?
\begin{itemize}
\item Yes, this was the most significant impactful change. Turning advantage normalization on increased the speed of learning and decreased the variance.
\end{itemize}
\item Did the batch size make an impact?
\begin{itemize}
\item Yes, the returns are lower stdev for larger batch size. 
\end{itemize}
